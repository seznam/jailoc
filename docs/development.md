# Development

This page is for contributors. It covers how to build and test the project locally, the CI/CD pipeline, what ships inside the default workspace image, and the coding conventions the codebase follows.

## Prerequisites

- Go 1.26+
- Docker Engine, for building workspace images
- macOS on Apple Silicon or Linux (amd64, experimental arm64) with KVM, for running workspace VMs

## Building and testing

```bash
# Build the binary
go build ./cmd/jailoc

# Embed jailoc-guest, the VM init (release builds do this automatically)
go generate ./internal/guestbin
go build ./cmd/jailoc

# Embed the VM runtime (release builds do this automatically); without it,
# set [vm] runner and lib_dir. Needs a go-microvm checkout at the revision
# pinned in go.mod, see the script header for other requirements.
scripts/vm-runtime/build-init.sh /path/to/go-microvm /tmp/init
scripts/vm-runtime/build-runtime-linux.sh /path/to/go-microvm /tmp/init internal/vm/runtimebin/linux-amd64
go build ./cmd/jailoc

# Verify all packages compile (pre-commit)
go build ./...

# Run unit tests
go test ./...

# Run the VM integration tests (needs KVM or macOS, a go-microvm runner and host Docker)
JAILOC_VM_RUNNER=/path/to/go-microvm-runner JAILOC_VM_LIBDIR=/path/to/libs \
  go test -tags vmintegration -v -timeout 45m ./internal/vmintegration/

# Lint
go vet ./...
golangci-lint run

# Build jailoc together with its VM runtime (Linux only)
nix build .#jailoc
```

## CI/CD pipeline

The pipeline runs on GitHub Actions. Most workflows trigger on every branch and pull request; release workflows are gated on version tags (`v*`).

| Workflow | Trigger | Purpose |
|----------|---------|---------|
| CI | Pushes and pull requests to `main` | Unit tests (`go test`), golangci-lint, and a check that the embedded TUI plugin matches its source |
| Release | Tags matching `v*` — runs on `push` with `v*` ref | GoReleaser publishes static binaries, generates a GitHub Release with changelog and updates the Homebrew cask in `seznam/homebrew-tap` |
| Docs | Tags matching `v*` — runs on `push` with `v*` ref | Builds documentation with MkDocs and deploys to GitHub Pages |
| Pre-release | Manual (`workflow_dispatch`) with a ref and a version such as `1.20.0-rc.1` | Tags the ref and publishes GoReleaser binaries as a GitHub pre-release; no docs deploy, no release-please involvement |
| VM Integration | PRs and pushes to `main` touching VM code, manual | Builds the go-microvm runner and libkrun from the pinned revision and boots real workspace VMs on a GitHub-hosted x64 Linux runner with KVM (`go test -tags vmintegration ./internal/vmintegration/`) |
| Nix | Pushes and pull requests to `main` | Formatting check (`nix fmt`) and `nix flake check --all-systems`, plus `nix build .#jailoc` and `nix run . -- --help` on x86_64 and aarch64 Linux runners |
| Nix vendorHash | `go.mod`/`go.sum` pushes to `main`, Dependabot PRs, manual | Recomputes the `vendorHash` in `nix/jailoc.nix` and publishes it, see [Dependabot Nix vendorHash](#dependabot-nix-vendorhash) |
| VM runtime | Called by the release workflows; pull requests touching `scripts/vm-runtime/` | Builds the VM runtime (go-microvm runner, libkrun from source with cargo-auditable and a musl guest init (`build-init.sh`), libkrunfw; Linux in go-microvm's builder image pinned by digest in `scripts/vm-runtime/builder-image.sh`) for darwin/arm64, linux/amd64 and linux/arm64, the libkrunfw corresponding source (`build-runtime-source.sh`) and the runtime license notices (`build-runtime-notices.sh`, cargo-about for libkrun crates); uploads artifacts only when called by a release |

GoReleaser runs `go generate ./internal/guestbin` before building, so release binaries embed `jailoc-guest`, and refuses to build unless the release workflow has placed all VM runtimes in `internal/vm/runtimebin/` and the runtime notices and source in `build/vm-runtime/`. It builds static binaries (`CGO_ENABLED=0`) for `darwin/arm64`, `linux/amd64` and `linux/arm64`, adds `THIRD_PARTY_NOTICES` (generated by `scripts/third-party-notices.sh`) to every archive and attaches `jailoc_<version>_vm-runtime-source.tar` and SPDX SBOMs (syft) of the archives and VM runtimes to the release. For stable tags it also pushes `Casks/jailoc.rb` to [`seznam/homebrew-tap`](https://github.com/seznam/homebrew-tap) over SSH with the `HOMEBREW_TAP_DEPLOY_KEY` secret (the private half of a write-enabled deploy key on the tap). The secret lives in the `homebrew-tap` environment, which only `main` and `v*` tags can deploy to; pre-release tags skip the tap and never receive the key. The release job then attests build provenance for every file in `checksums.txt`. Configs live in `.goreleaser.yml` and `.github/workflows/`.

### Nix package

| File | Responsibility |
|------|----------------|
| `flake.nix` | Systems, formatter (alejandra), apps and dev shells; imports `nix/` for the packages |
| `nix/default.nix` | Dependency map: wires the runtime recipes together and passes the VM runtime to `nix/jailoc.nix` on Linux |
| `nix/jailoc.nix` | jailoc itself: embedded `jailoc-guest`, `vendorHash`, runtime paths as link-time variables |
| `nix/runtime/sources.nix` | Upstream pins and hashes for go-microvm, libkrun, libkrunfw and the Linux kernel; checks the go-microvm pin against `go.mod` |
| `nix/runtime/libkrun-init.nix` | Static musl guest init (`init.krun`) that libkrun embeds |
| `nix/runtime/libkrunfw.nix` | libkrunfw with its bundled Linux kernel, built offline from the pinned kernel tarball |
| `nix/runtime/libkrun.nix` | libkrun with jailoc's patches and the musl init, linked against libkrunfw |
| `nix/runtime/go-microvm-runner.nix` | go-microvm runner linked against jailoc's libkrun; checks go-microvm's `versions.env` against `sources.nix` |

jailoc receives the runtime through two link-time variables,
`internal/cmd.defaultVMRunner` and `internal/cmd.defaultVMLibDir`. A configured
`[vm] runner` / `lib_dir` wins over these package defaults, and the package
defaults win over the embedded runtime. Build a single runtime component for
debugging with `nix build .#jailoc.runtime.<component>`, where `<component>` is
one of `libkrunInit`, `libkrunfwJailoc`, `libkrunJailoc` or `goMicrovmRunner`.

Bump procedure:

- **go-microvm revision** (the `replace` line in `go.mod`): update
  `goMicrovmRev` and its hash in `nix/runtime/sources.nix`, and the
  `vendorHash` in `nix/runtime/go-microvm-runner.nix`. Evaluation fails with a
  message naming both files until `sources.nix` matches `go.mod`.
- **libkrun or libkrunfw version** (go-microvm's `versions.env`): update the
  versions and hashes in `nix/runtime/sources.nix` and the Cargo vendor hash in
  `nix/runtime/libkrun.nix`. The runner build fails while `versions.env` and
  `sources.nix` disagree.
- **libkrun patches**: `nix/default.nix` applies every `*.patch` in
  `scripts/vm-runtime/libkrun-patches/` in lexical order, the same set the
  release build uses. No Nix change is needed.

#### macOS

The Nix package builds the VM runtime for Linux only; on aarch64-darwin it
ships jailoc without a runtime. An aarch64-darwin runtime needs:

1. A `nix/runtime/libkrunfw-darwin.nix` recipe (not present in the
   repository) that builds `libkrunfw.5.dylib` from upstream's
   `libkrunfw-prebuilt-aarch64.tgz` release asset, which contains `kernel.c`
   and a `Makefile`. The v5.6.2 asset's sha256 is
   `adef6739cc3bda2a1b57f04c08ccbfdf206a6c831d76b32de1beddc0e7984e86`.
   `scripts/vm-runtime/build-runtime-darwin.sh` takes the same approach for
   release builds.
2. In `nix/default.nix`: `pkgs.pkgsCross.aarch64-multiplatform.pkgsStatic.stdenv`
   for `nix/runtime/libkrun-init.nix` on that platform (the guest init is a
   Linux binary even when built on a macOS host; nixpkgs' `libkrun-efi`
   package does the same), the darwin libkrunfw recipe, and a `vmRuntime`
   value for darwin.
3. In `nix/runtime/libkrun.nix`: an offline build (the upstream darwin
   `Makefile` downloads a Debian sysroot unless `SYSROOT_LINUX` is set or the
   prerequisite is removed), `fixDarwinDylibNames`, and no libkrunfw link via
   RUSTFLAGS. On darwin libkrun opens `libkrunfw.5.dylib` through the runner's
   `DYLD_LIBRARY_PATH`, not as a build-time dependency.
4. In `nix/runtime/go-microvm-runner.nix`: removing the
   `-L/opt/homebrew/lib -L/usr/local/lib` and matching include flags from the
   darwin cgo directives in `krun/context.go`, so an unsandboxed darwin builder
   never links a Homebrew libkrun; signing the runner in `postFixup` with
   `darwin.sigtool` and
   `codesign --entitlements <go-microvm source>/assets/entitlements.plist -f -s -`;
   `dontStrip = true`, because stripping removes the entitlements; and an
   `otool -L` linkage check.
5. A `macos-15` build job in `.github/workflows/nix.yml`. CI proves only the
   build, signature and linkage: GitHub's macOS runners can't run nested
   Hypervisor.framework VMs, so booting a VM needs a real Apple Silicon Mac.

### Dependabot Nix vendorHash

[`nix-vendor-hash.yml`](https://github.com/seznam/jailoc/blob/main/.github/workflows/nix-vendor-hash.yml) handles `go.mod`/`go.sum` changes pushed to `main`, manual runs, and same-repository PRs targeting `main` authored by Dependabot. The PR gate checks the author, not the actor, so maintainer-triggered updates also qualify.

- **`calculate`** checks out the exact source commit with read-only repository permissions. It runs `nix-update` and, when `nix/jailoc.nix` changes, formats, checks, builds, and runs the package. It passes only the updated `vendorHash` string as a job output. The job uses no Nix cache: its output feeds a job with write permissions, and without a cache there is no cache-poisoning path into it. Its timeout covers a cold build of the VM runtime.
- **`publish`** checks out the same commit on a fresh runner with write permissions. It validates the hash format and replaces the single `vendorHash` assignment without running Nix or repository scripts. It commits only `nix/jailoc.nix` to the Dependabot branch, or opens the maintenance PR against `main` for push/manual runs. The Dependabot push uses `--force-with-lease` against the original PR head SHA, so it is rejected if the branch advanced or was deleted while `calculate` ran.

Nix build sandboxing does not isolate the entire job: `nix run` executes the application outside the build sandbox. Separate runners prevent that execution from modifying the publication environment or capturing its write token. The workflow definition itself can still be modified in a PR; the same-repository Dependabot gate is not an absolute trust boundary. Publication uses `GITHUB_TOKEN`; the Dependabot branch commit includes [`[dependabot skip]`](https://docs.github.com/en/code-security/how-tos/secure-your-supply-chain/manage-your-dependency-security/manage-dependabot-prs#allowing-dependabot-to-rebase-and-force-push-over-extra-commits), allowing Dependabot to rebase and replace it.

After the token-generated push, a contributor with write access must select **Approve workflows to run** on the PR to start the resulting approval-required `pull_request` CI runs. See [approving workflow runs](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/approve-runs-from-forks). [`GITHUB_TOKEN` pushes do not trigger `push` workflows](https://docs.github.com/en/actions/concepts/security/github_token#when-github_token-triggers-workflow-runs).

## Project conventions

### Module

```
github.com/seznam/jailoc
```

### Commit format

```
type(scope): description
```

Valid types: `feat`, `fix`, `docs`, `chore`, `refactor`, `test`. Use imperative mood in the description.

### Error handling

Always wrap errors with context. Never return a bare `err`.

```go
// correct
return fmt.Errorf("resolve workspace: %w", err)

// wrong
return err
```

There are no custom error types in this codebase. `fmt.Errorf` wrapping is the only pattern used. There is no logging library either: `fmt.Printf` handles user-facing output, and errors propagate up the call stack.

### File organization

One file per package concern: `docker.go`, `workspace.go`, `config.go`. When a concern grows large enough to split, create a new file with a descriptive name (e.g. `fetch.go` for HTTP fetching inside the `docker` package). All packages live under `internal/` — nothing is exported.

### Testing

Unit tests live beside their source files as `*_test.go`. VM integration tests live in `internal/vmintegration/` and require the `vmintegration` build tag. Tests use `t.Parallel()` and a table-driven style with `t.Run`. There are no mocks, fixtures, or testdata directories.

## Developing inside a jailoc workspace

`dev/Dockerfile.jailoc` is a workspace overlay that extends the default image with the Go toolchain, gopls, and golangci-lint. It lets you develop jailoc inside a jailoc workspace.

Add to `~/.config/jailoc/config.toml`:

```toml
[workspaces.jailoc]
paths = ["/path/to/jailoc"]
dockerfile = "https://raw.githubusercontent.com/seznam/jailoc/main/dev/Dockerfile.jailoc"
```

Then run `jailoc up jailoc`. The standard build and test commands work inside the VM unchanged. The Docker integration tests (`-tags integration`) also need `enable_docker = true`; the VM integration tests cannot run inside a workspace VM.
